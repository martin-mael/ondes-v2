## How the owner works (keep doing it this way)

- **Waves:** one GitHub issue = one Claude session (`start_session`, fresh context, its own worktree, branch `<issue>-<slug>`). Each session opens one PR, moves its issue to "In review", and **never merges**. The briefs say:
  - which ADRs to read;
  - who they coordinate with, via SendMessage;
  - the dev-stack rules;
  - that they may spawn Haiku subagents for chores.
- **Review:** 2 Haiku reviewers per PR, one for bugs and one for acceptance criteria, conventions and tests. Spot-check the big findings yourself, then present a triaged list.
  - The owner usually says "fix all, including minor".
  - Send each session its findings; cross-session items go to whichever session owns them.
- **Integration:**
  1. Merge the PRs into one branch (`mN-wave-K`), off main.
  2. Resolve the additive conflicts with `tools/resolve.py`. It handles split route and nav objects. Check its output.
  3. Regenerate migrations with `tools/regen-migrations.sh`. It restores custom migrations verbatim.
  4. Add the glue the sessions ask for.
  5. Run everything: lint, typecheck, test, integration with `.env.example` loaded and the ffmpeg PATH shim, then the engine checks.
  6. Open one combined PR.
- **Merging:** **ask before merging**. When the owner says yes, squash-merge, close the originals as superseded, and delete their branches.
- **Local UI testing:** since wave 7, the owner wants the app running locally to test before merging. See below.
- **UI preferences:** they're in `CLAUDE.md` under "Web app", covering accent strips, loaders, unsaved guards, station time only and heading sizes. Put them into every web brief and review prompt.
- **Language and tone:** the owner writes in English, sometimes in French. The UI is FR and EN.

## Gotchas found along the way

- **Stray workers.** A worker left running in another worktree, on the shared RabbitMQ vhost `/ondes` but with its own database, steals jobs and "succeeds" them against the wrong database. Check `ps -eo pid,command | grep src/main.ts` when analysis looks stuck. The classifier may not let you kill another session's process; ask the owner.
- **RabbitMQ URLs.** Default URLs in tests must include the `/ondes` vhost. CI sets `RABBITMQ_URL`, so a missing vhost only fails locally.
- **zsh.** zsh doesn't word-split `$var` lists. Pass file lists explicitly, or a merge gets committed with conflict markers in it. Grep for `^<<<<<<<` before committing.
- **Commit hygiene.** Commit format changes before the next merge. `git add -A` during a conflicted merge stages the markers.
- **ADR numbers.** Parallel sessions pick colliding ADR numbers. Tell them the next free number in the brief, and check at review.
- **Classifier blocks.** The auto-mode classifier has blocked `git push` and `kill` here once. If that happens, give the owner the exact command.

## Tools (`.handoffs/tools/`)

- **`resolve.py <files…>`:** keeps both sides of additive conflicts, ours then theirs. It closes split objects (router routes, nav items). Review the result.
- **`regen-migrations.sh`:** run it during a merge with a conflicting drizzle journal. It keeps HEAD's journal, regenerates the incoming migrations and diffs their SQL against the originals. Hand-written migrations are restored with `drizzle-kit generate --custom`.
- **`create_issues.py <spec.md>` with `state.json`:** creates issues from blocks shaped like `@@ TASK <parentKey> | <key> | <title> | <milestone> | <labels> | <priority> | <size>`, adds them to project #1 with its fields, and links each to its parent epic. `state.json` maps keys to issue numbers; epic keys are in it, e.g. `foundations` = #2, `library` = #16.
- **Unblocked issues:** the GraphQL query used each wave lists open leaf issues with their open `blockedBy`:

```sh
gh api graphql --paginate -f query='query($endCursor:String){repository(owner:"martin-mael",name:"ondes-v2"){issues(first:100,states:OPEN,after:$endCursor){pageInfo{hasNextPage endCursor} nodes{number title milestone{title} subIssues(first:1){totalCount} blockedBy(first:20){nodes{number state}}}}}}' \
  -q '.data.repository.issues.nodes[] | select(.subIssues.totalCount==0) | [.number, (.milestone.title // "-"), ([.blockedBy.nodes[]|select(.state=="OPEN")|.number]|map(tostring)|join(",")), .title] | @tsv'
```
