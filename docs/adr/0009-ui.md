# ADR 0009: Web UI stack and app shell

- Status: accepted
- Date: 2026-10-21
- Issue: #9

## Context
The web app is a power-user tool: dense tables, many pickers and dB/time inputs, and later waveform, timeline and segue editors. Several agents build feature UIs in parallel (`apps/web/src/features/*`), so the shell, the design system and the conventions must be settled first and must fit our tooling (Biome, TypeScript 7 type checking, Vitest, pnpm workspaces with source-first packages).

## Decisions

### Components: shadcn/ui on Base UI
- **shadcn/ui**, CLI pinned at `shadcn@4.22.1`, Tailwind CSS v4, Vite template. Initialised with:
  `pnpm dlx shadcn@4.22.1 init --template vite --base base --preset bxxqw5nCS --pointer`
  (flags checked with `init --help` on that version).
- `--base base`: **Base UI** primitives (`@base-ui/react`), not Radix. Base UI ships a native Combobox/Autocomplete and Number Field, which our pickers and dB/time inputs need, and it's actively maintained. Composition uses the `render` prop, not `asChild`: `<Button nativeButton={false} render={<Link to="/" />} />`, `<DropdownMenuTrigger render={<SidebarMenuButton />} />`.
- `--preset bxxqw5nCS`: style `mira`, theme `blue` on base color `neutral`, chart color `neutral`, Inter for text and Nunito Sans for headings (`font-heading`), Lucide icons, default radius and menu color, subtle menu accent.
- `--pointer`: pointer cursor on buttons.
- shadcn now merges classes with its own `cn` package (clsx + tailwind-merge in one); generated components import it directly.

### Where components live: `apps/web/src/ui/`
- `components.json` aliases point `components`, `ui`, `utils`, `lib` and `hooks` at `@/ui` (`@/ui/lib/utils`, `@/ui/hooks`), so `pnpm dlx shadcn@4.22.1 add <name>` (run in `apps/web`) writes straight into `src/ui/`.
- `ui/` is the one shared design system: generic, no domain logic, and features never fork a component. A feature that needs a variant adds it to `ui/` (or wraps it in its own folder).
- The theme provider is in `ui/theme-provider.tsx` (generated by `init`); `ui/sonner.tsx` uses it instead of `next-themes`, so `next-themes` isn't a dependency.
- Waveform, timeline and segue editors (#24, #51, #58) are custom canvas/SVG components styled with the same CSS variables, not shadcn primitives.

### Themes
Light and dark come from the preset's CSS variables (`src/app/index.css`: `:root` and `.dark`). The default follows `prefers-color-scheme`; the user can force light, dark or system from the user menu (or the header on signed-out pages). The choice is stored per browser (`localStorage["ondes.theme"]`).

### Fitting our tooling
- **Biome** formats generated components to our style (single quotes, semicolons) and lints them. After `shadcn add`, run `pnpm format`. A Biome override for `apps/web/src/ui/**` turns off the handful of rules shadcn's code trips (`noLabelWithoutControl`, `useSemanticElements`, `useExhaustiveDependencies`, `noArrayIndexKey`, `noDocumentCookie`, `noDoubleEquals`), so regenerated components don't need hand edits; app code keeps the full rule set. Biome's CSS parser has `tailwindDirectives` on for `@theme`, `@apply` and `@custom-variant`.
- **TypeScript 7**: `apps/web/tsconfig.json` extends the base config (strict, `noUncheckedIndexedAccess`, erasable syntax only) and adds DOM libs, `jsx: react-jsx`, `vite/client` types and the `@/*` path. Generated components pass as is.
- **Imports**: app code uses `.ts`/`.tsx` extensions on relative imports, like the rest of the repo. shadcn's `@/ui/...` alias imports stay extensionless (Vite resolves them; that's how the CLI writes them).
- **Vitest**: the root config has two projects, `node` (everything else) and `web` (`apps/web/vitest.config.ts`: happy-dom, the app's Vite config, `*.test.{ts,tsx}`). `pnpm test` runs both.
- shadcn's ESLint/Prettier scaffolding isn't kept, and `typescript` stays the root's TypeScript 7.

### App shell
- **React 19 + Vite 8 + TanStack Router and Query**, exact versions.
- **Code-based routes** (`src/app/router.tsx`), not file-based routing: no generated route tree, no extra Vite plugin, and features keep their code in `features/<feature>`. A feature adds a route with `getParentRoute: () => stationRoute` (`/stations/$stationId/...`) and one entry in `src/app/shell/nav.ts`. Signed-out pages hang under the `_auth` layout; signed-in pages under `_app`, whose `beforeLoad` redirects to `/login?redirect=…` (same-app paths only).
- **Data**: TanStack Query does the caching; route loaders call `ensureQueryData`. `meQuery` is `null` when signed out. The org/station switcher reads `GET /api/v1/orgs` (orgs the user belongs to, with the stations they can reach and their role). This issue adds it in `apps/api/src/modules/orgs`, because no other route lists stations or names.
- **API client** (`src/app/api/client.ts`): same-origin `fetch` with the session cookie, JSON bodies, responses validated with the `@ondes/shared` zod contracts. Contracts type timestamps as `Date`, so ISO strings in `…At` fields are revived before validation (API DTOs follow that naming). Errors become `ApiError { status, code, message, details }`.
- **Global error handling** (`src/app/errors.ts`): queries, mutations and the SSE stream report errors to one handler. `401 unauthenticated` resets the session and goes to sign-in (then back); `403 two_factor_required` goes to `/account?reason=two_factor_required`. Forms show their own errors with translated messages.
- **Forms**: uncontrolled inputs read with `FormData`, validated with the shared contract (`useZodForm`), errors rendered with shadcn's `Field` components. No form library yet.
- **i18n**: FR + EN from day one with a small typed dictionary (`src/app/i18n/messages.ts`, `fr` must match `en`'s keys) and zod's own locales for validation messages. The browser language picks the default; the user can switch.

### Real-time: SSE
- `apps/api/src/plugins/sse.ts`: `GET /api/v1/stations/:stationId/events`, guarded by `station:read`. One RabbitMQ fanout subscription per api process feeds every open stream.
- **Allowlist, not convention.** Only event types declared in `contracts/events.ts` are forwarded. Each type needs an entry in `realtimeEventPermissions`, and the type checker refuses a missing one. Each event is re-parsed with its strict schema and re-serialised, so undeclared types are dropped and undeclared fields are stripped. A subscriber gets an event only if it's for their station and they hold that type's permission.
- **Best-effort.** The fanout has no persistence or acknowledgement; it's for UIs. Anything with side effects consumes a durable queue.
- **Revocation.** Every 60 s, an open stream re-runs its access check (`GET …/events/access`, the same guard). A revoked session, key or membership closes it, and lost permissions are applied. The stream also closes when its session or key expires. Otherwise it ends after about 10 minutes, minus up to 10 % jitter, and the browser reconnects.
- **Limits.**
  - At most 5 open streams per session or API key; a new one closes the oldest.
  - A client more than 1 MB behind is dropped.
  - Closed and errored sockets are forgotten at once.
- **`Last-Event-ID`.** Each process keeps the last 200 events per station and replays what the client missed: from the header on browser retries, or from `?lastEventId=` when the web app reconnects by hand. An unknown id (too old, or another replica) replays nothing, and the page refetches.
- **`server.clock` and heartbeats.** `server.clock` is stream-only (no station, no `id`). It's sent on connect and every 10 s; the web app derives the clock offset and ticks locally. Heartbeat comments go out every 15 s.
- **Headers.** `reply.hijack()` skips Fastify's `onSend` hooks, so the plugin writes its own headers: `text/event-stream`, `no-cache, no-transform`, `nosniff`, `x-accel-buffering: no`.
- **Web.** `<SseProvider>` opens one EventSource per open station; `useSse`, `useSseEvent(type, …)`, `useSseStatus` and `useServerClock` read it. When the browser gives up (non-200), the provider calls the access check to learn why. It reports 401/403/404 like any api error; otherwise it reconnects with backoff, carrying the last event id.

### Dev and production
- `pnpm dev` runs the api (reading the repo's `.env`) and Vite on :5173, which proxies `/api` (SSE included) to the api's `API_PORT`, so cookies stay same-origin.
- `pnpm --filter @ondes/web build` produces static files in `apps/web/dist`. Serving them (Caddy: static files plus a `/api` reverse proxy, no buffering on the SSE route) is the installer's job (#84); no web image yet. CI runs the build.

## Consequences
- Feature agents add components with the pinned CLI, then `pnpm format`; they don't edit generated components for style.
- The bundle is one ~775 kB chunk (240 kB gzip). Route-level code splitting can come when feature pages land.
- Base UI's API differs from Radix (and from most shadcn examples online): `render` instead of `asChild`, `nativeButton={false}` for buttons rendered as links.
- Swapping Base UI, the router or the styling approach needs a new ADR.
