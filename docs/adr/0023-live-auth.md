# ADR 0023: DJ identities and the harbor auth callback

- Status: accepted
- Date: 2026-10-22
- Issue: #63 (epic #62). Builds on ADR 0002 (live input, auth webhook), 0007 (station template)
  and 0008 (per-station secrets, live port pool). Consumers: the harbor pool and live switching
  (#64), live slots (#65).

## Context
Until now a station's live input took one shared password (`ENGINE_LIVE_PASSWORD`, generated
per station by the lifecycle). Vandale has several DJs, guests for one night, and DJs who share
a machine, so each needs their own credentials, revocable on their own, and limited to their
shows. ADR 0002 already planned for this: `input.harbor` can ask Node about every login through
a webhook (`live_auth_url`, body `{user, password, address}`, 2xx = accept).

## Decision

### A streamer per DJ, per station
`streamer` (`packages/db/src/schema/live.ts`): a display name, a username unique per station
(case-insensitive, lowercase, 2–32 of `[a-z0-9._-]`), an argon2id password hash (the auth
module's parameters), `enabled`, an optional `expires_at`, `any_time`, and an optional link to a
member (null for guests; deleting the user turns the streamer into a guest). `streamer_show`
lists the shows it may connect for, with composite keys on both sides so it can't point at
another tenant's show.

- **Passwords are generated by default** (24 characters, no look-alikes, no `:`), returned once
  by the create and "new password" calls and never again. A manager may type one instead
  (12+ characters). DJ software stores the password in clear, so a long random one costs nothing.
- **Audit:** create, update, new password and delete are audited like every mutation; the diff
  never carries the password or its hash (`password: set | generated`). Accepted logins are
  audited as `streamer.connect` (actor `system:engine`, the source address) and stamp
  `last_connected_at`. Refused logins are only logged: the live port is public, and a flood of
  bad logins must not fill the audit log.

### The callback: `POST /internal/engine/stations/:stationId/live-auth`
The lifecycle renders `live.authUrl` into every station's script (`engineSettingsFor`), so the
shared password is no longer used once an engine restarts with it. The template sends the
station's control token as `Authorization: Bearer` on the webhook, like its event posts, and the
route checks it in constant time (same lookup as the events route, `lifecycle.tokenFor`).
Without the token: 401. Internal only, like `/internal/engine/…/events`: never routed by Caddy.

A login passes when, in order:
1. the username exists on **that station** (the station comes from the URL the token proved);
2. the password matches the hash (`@node-rs/argon2` `verify`, constant time); an unknown
   username burns a dummy verify so the answer time doesn't reveal it;
3. the streamer is enabled and not expired;
4. it may connect now: `any_time`, or an occurrence of one of its shows (not a rerun) overlaps
   `[now, now + 15 min)`, i.e. from 15 minutes before the slot (soundcheck) until it ends. The
   occurrences come from the shows module (`getOccurrences`), station time and DST included.

200 accepts; 403 refuses, with the reason logged, never returned. A per-api-replica limiter
refuses an address after 10 failed logins in 10 minutes without checking the password (argon2
is deliberately slow and the port public). It throttles guessing; it is not an account lockout,
which anyone could use to lock a DJ out before their show.

Connecting is not going on air: Node still opens the live gate (`POST /v1/live`), at a live
slot's start (#65) or by hand (#64).

### Shoutcast clients
Shoutcast (ICY) sources send no username. When the login name is empty or a placeholder
(`source`, `admin`, `shoutcast`, reserved as usernames), a `username:password` password is
split at the first colon. BUTT's Icecast mode defaults the user to `source`, so this form also
works there. Harbor only opens the ICY port (`port + 1`) with `icy=true`, which the template
doesn't set and the lifecycle doesn't publish: the connection page says so and shows the
Icecast settings; the harbor pool (#64) can open it.

### Connection info
`GET /api/v1/stations/:stationId/live/connection`: the public host (`LIVE_PUBLIC_HOST`, default
the app URL's host), the station's published live port (`engine_port`, null before its engine
first starts), the mount from its engine settings and the accepted formats. The web page turns
it into BUTT, Mixxx and OBS settings.

### Permissions
`live:manage` (station managers) manages streamers. `live:read` lists them, but a member without
`live:manage` only sees the streamers linked to them, and with `live:broadcast` (presenters) may
make a new password for those.

## Consequences
- An engine started before this change keeps the shared password until it is re-rendered
  (restart, or any reconcile). Station managers must create streamers before their DJs' next set.
- `engine/tests/live-auth/run.ts` checks the whole path on the real template and image: good
  credentials connect, wrong, unknown, disabled, out-of-slot and shared-password logins are
  refused, the Shoutcast form connects. It needs the dev Postgres, Docker and ffmpeg, so it's
  not in CI yet.
- #64 (harbor pool) keeps this callback: each harbor input posts to the same route; if it needs
  to know which streamer connected, the 200 body can carry the streamer id (additive).
