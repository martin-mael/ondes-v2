# Icecast in production (#32)

One Icecast 2.5 (`libretime/icecast:2.5.0-alpine`) serves every station. Its config is
generated by the api from the stations in the database; Caddy terminates TLS on 443 in front
of it. The installer (#84) wires this up. This page is what it has to do.

```
listeners ──443/TLS──▶ Caddy ──http──▶ icecast:8000 ◀── each station's engine (Liquidsoap)
                                         ▲    ▲
                 /srv/ondes/icecast/     │    └── api: listener stats poller (/admin/stats)
                 icecast.xml ────────────┘
                 (written by the api, read by deploy/icecast/entrypoint.sh)
```

## Mounts

Per station, in its namespace `/<station-slug>/…` (settings `outputs`, schema in
`apps/api/src/modules/engine/config/settings.ts`, plan in `apps/api/src/modules/engine/icecast`):

| Mount | Default | Format |
|---|---|---|
| `/<slug>/mp3` | on | MP3 128k CBR, 44.1 kHz stereo: browsers, VLC, car radios, smart speakers |
| `/<slug>/aac` | on | AAC-LC 128k (ADTS, ffmpeg's native encoder: HE-AAC needs fdk-aac, which is not free software) |
| `/<slug>/opus` | opt-in | Ogg/Opus 96k: best quality per bit, but some hardware players can't play it |

Each mount gets, from its output settings: `max-listeners` (default 500), `burst-size` (64 KiB,
about 4 s at 128k: fast start) below `queue-size` (512 KiB: a listener that lags further is
dropped; the schema refuses a burst ≥ queue, which breaks connections), `charset` UTF-8 (without
it, non-ASCII station names are garbled on MP3/AAC mounts), and:

- **Fallback** (on by default): `fallback-mount` = `/_ondes/<slug>/<format>.fallback.<ext>`, a
  file in Icecast's webroot holding the station's emergency loop in the mount's format.
  When the engine is not connected (stopped, restarting, crashed), listeners are moved to the
  file, which loops; `fallback-override all` moves them back when the engine reconnects, and
  `fallback-when-full` sends listeners above `max-listeners` there too. Measured
  (`icecast.int.test.ts`): a listener connected when the engine stops keeps receiving audio,
  longest gap 0.4–0.7 s; it is back on the live stream after the engine reconnects.
  Icecast doesn't pace file fallbacks: a client that reads as fast as it can gets the file
  faster than real time. Players read at playback speed, so this costs nothing in practice.
- **Intro** (off by default): `intro` = `/_ondes/<slug>/<format>.intro.<ext>`, sent to each new
  listener before the stream (a station ID). Verified byte for byte by the test.

The files live in a volume mounted at `/usr/share/icecast/web/_ondes` (read-only for Icecast),
`<slug>/<format>.{fallback,intro}.<ext>` with `ext` = `mp3`, `aac`, `ogg` (Opus/Vorbis: Icecast
types webroot files by extension, and `.ogg` is the one it knows). A missing fallback file
means listeners are disconnected when the engine stops, as without a fallback. Encoding them
from the station's emergency file and intro asset is a worker job (follow-up issue); the test
encodes sine tones with Liquidsoap (`apps/api/src/modules/engine/icecast/testing/assets.liq`).

## Config generation and reload

- The api renders `icecast.xml` for all stations (`renderIcecastConfig`) and writes it to
  `ICECAST_CONFIG_PATH` atomically, only when it changed: on boot, every 30 s
  (`ICECAST_SYNC_INTERVAL_MS`), and when code calls `sync.syncNow()` after a settings change.
  A station with invalid outputs is left out (and logged); it can't take the others down.
- **No secrets in the file.** The source, relay and admin passwords are placeholders
  (`env:ICECAST_SOURCE_PASSWORD`, …). The container fills them in from its own environment.
- `entrypoint.sh` (this folder) is the container's entrypoint. It waits for the file, fills in
  the passwords (any character allowed, XML-escaped), starts Icecast on the result
  (`/etc/icecast.xml`, mode 600), and checks the source file every 2 s
  (`ICECAST_CONFIG_POLL_SECONDS`). On a change it renders again and sends Icecast a **SIGHUP**.

**Why SIGHUP and not a restart.** Measured with the pinned image (`icecast.int.test.ts`):

| | Listeners | Sources (engines) | Applies |
|---|---|---|---|
| SIGHUP reload | stay connected; longest gap 128–136 ms (a 128k stream normally arrives in 150–250 ms bursts, so nothing audible) | stay connected | new and removed mounts, changed limits, fallback, intro: 2.8–3.4 s after the api wrote the file (1 s poll in the test + Icecast's reload queue) |
| Restart | **all cut** (within 0.3 s), players must reconnect | cut, Liquidsoap reconnects after its retry delay | everything |

A file Icecast can't parse is ignored on SIGHUP: it logs `Error parsing config, not replacing
existing config` and keeps running on the previous one (tested). Changes that need a restart:
listen sockets (port, bind address). The generator keeps them fixed.

**Icecast 2.5.0 reload deadlock.** After any `/admin/listclients` request (XML or JSON) on a mount
that had a listener, the next SIGHUP deadlocks Icecast: it stops answering anything, and the
container stays "up". Reproduced every time; `/admin/stats` doesn't trigger it. So:
- nothing in Ondes calls `listclients` (the poller only reads `/admin/stats`), and nobody should
  use the admin web UI's "List clients" page in production;
- `entrypoint.sh` probes Icecast every 10 s (`ICECAST_WATCHDOG_SECONDS`) and kills it after three
  failed probes, so the container exits and `restart: unless-stopped` brings it back (about 20 s
  in the test, listeners cut). Re-test when the image is bumped.

## Production compose (for #84)

```yaml
services:
  icecast:
    image: libretime/icecast:2.5.0-alpine
    entrypoint: [sh, /ondes/entrypoint.sh]
    restart: unless-stopped
    environment:
      ICECAST_SOURCE_PASSWORD: ${ICECAST_SOURCE_PASSWORD}   # same value on the api (#35)
      ICECAST_ADMIN_PASSWORD: ${ICECAST_ADMIN_PASSWORD}
    expose: ['8000']            # no `ports:`: only Caddy, the engines and the api reach it
    volumes:
      - ./icecast/entrypoint.sh:/ondes/entrypoint.sh:ro
      - icecast-config:/config:ro                       # the api writes icecast.xml here
      - stream-assets:/usr/share/icecast/web/_ondes:ro
  api:
    environment:
      ICECAST_CONFIG_PATH: /srv/ondes/icecast/icecast.xml
      ICECAST_PUBLIC_HOSTNAME: stream.example.org
      ICECAST_URL: http://icecast:8000
      ICECAST_ADMIN_USER: admin
      ICECAST_ADMIN_PASSWORD: ${ICECAST_ADMIN_PASSWORD}
      ICECAST_SOURCE_PASSWORD: ${ICECAST_SOURCE_PASSWORD}
    volumes:
      - icecast-config:/srv/ondes/icecast
```

- **One source password for every engine** (agreed with #35): set `ICECAST_SOURCE_PASSWORD` on the
  api to the Icecast container's value. If the api has none, the lifecycle (#35) generates one
  per station, which this Icecast config doesn't know, and engines can't connect. Per-station
  source passwords (Icecast per-mount `<password>`) are a possible follow-up.
- The api writes the file as world-readable (Icecast runs as uid 1000); it holds no secret.

## Caddy on 443

Streams are served on their own host name (the `ICECAST_PUBLIC_HOSTNAME`), so stream URLs are
`https://stream.example.org/<slug>/mp3`. Caddy gets the certificate (Let's Encrypt) and proxies
only the public paths:

```caddyfile
stream.example.org {
	# Mounts are /<station-slug>/<format>; slugs are [a-z0-9-]. Plus the status JSON for
	# players/embeds. Never /admin (Icecast's admin API stays on the internal network): it
	# has the same shape as a mount, hence the explicit exclusion.
	@public {
		path_regexp ^/([a-z0-9-]+/[A-Za-z0-9_.-]+|status-json\.xsl)$
		not path /admin /admin/*
	}
	handle @public {
		reverse_proxy icecast:8000 {
			# Live audio: no buffering, no response timeout.
			flush_interval -1
			transport http {
				read_timeout 0
				write_timeout 0
			}
		}
	}
	handle {
		respond 404
	}
}
```

- `flush_interval -1` matters: otherwise Caddy buffers the never-ending response and players
  stall. Caddy streams HTTP/1.1 and HTTP/2 responses, so browsers, VLC and mobile players all
  work over TLS (the issue's acceptance; check them by hand on the installed server).
- Engines connect to `icecast:8000` on the internal network, never through Caddy.
- A station slug `admin` would collide with Icecast's admin API; keep it reserved.
- Checked against the integration stack with `caddy:2.10.2-alpine` and `tls internal`: MP3 and
  AAC play over HTTP/2 + TLS (ffprobe/ffmpeg decode them), `/admin/stats` answers 404.
- Behind a CDN (Cloudflare), add a cache-bypass rule for the stream host.
- **GDPR.** Icecast logs requests to stdout; behind Caddy every request comes from Caddy's
  address, so Icecast's logs hold no listener IP. Caddy's access log is off unless configured
  (keep it off for the stream host, or drop `remote_ip`). The stats poller stores counts only.

## Listener stats

`apps/api/src/modules/engine/icecast/poller.ts` reads `/admin/stats` every 15 s and records, per
mount and minute, the number of samples, sum, min and max of listeners, and how many samples had
the engine connected (`stream_listener_minute`, `@ondes/db` `recordListenerSamples` /
`listListenerMinutes`). Listeners parked on a mount's fallback file count for that mount. A
mount without its engine for 60 s raises a `stream.source_missing` warning through the alert
framework (#33), resolved when the engine is back.
