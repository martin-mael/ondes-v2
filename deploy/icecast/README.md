# Icecast in production (#32)

One Icecast 2.5 (`libretime/icecast:2.5.0-alpine`) serves every station. Its config is
generated by the api from the stations in the database; Caddy terminates TLS on 443 in front
of it. The installer (#84) wires this up. This page is what it has to do.

```
listeners ──443/TLS──▶ Caddy ──http──▶ icecast:8000 ◀── each station's engine (Liquidsoap),
                                         ▲    ▲          with its own source password
                 icecast-config volume   │    └── api: listener stats poller (/admin/stats)
                 icecast.xml ────────────┘
                 (written by the api, read by deploy/icecast/entrypoint.sh)
                 stream-assets volume: fallback/intro files (deploy/icecast/encode-assets.sh)
```

## Mounts

Per station, in its namespace `/<station-slug>/…` (settings `outputs`, schema and defaults in
`apps/api/src/modules/engine/config/settings.ts`, plan in `apps/api/src/modules/engine/icecast`):

| Mount | Default | Format |
|---|---|---|
| `/<slug>/mp3` | on | MP3 128k CBR, 44.1 kHz stereo: browsers, VLC, car radios, smart speakers |
| `/<slug>/aac` | on | AAC-LC 128k (ADTS, ffmpeg's native encoder: HE-AAC needs fdk-aac, which is not free software) |
| `/<slug>/opus` | opt-in (`opusOutput`) | Ogg/Opus 96k: best quality per bit, but some hardware players can't play it |

Each mount gets, from its output settings: `max-listeners` (default 500), `burst-size` (64 KiB,
about 4 s at 128k: fast start) below `queue-size` (512 KiB: a listener that lags further is
dropped; the schema refuses a burst ≥ queue, which breaks connections), `charset` UTF-8 (without
it, non-ASCII station names are garbled on MP3/AAC mounts), its station's source password, and
the fallback and intro below. The slugs `admin` and `assets` are reserved (`slugSchema`): they
are Icecast paths.

## Source passwords: one per station

Every `<mount>` carries `<password>`: its station's own source password. Tested on the pinned
image (`icecast.int.test.ts`): a mount with its own password refuses every other one, and the
global `<source-password>` only opens undeclared mounts. `entrypoint.sh` makes that global one
random, known to nobody. So a station's engine sources its own mounts and nothing else, even
if its settings name another station's mount (they are also rejected when the plan is built:
`mountsOutsideNamespace`).

- **With the engine lifecycle (#35)**: the password is the station's stored, encrypted secret,
  `app.engineLifecycle.secretsFor(scope).icecastSourcePassword`, the one its engine gets. The api
  syncs Icecast in the lifecycle's `onBeforeCreate` hook, before every engine container create
  (first start, config change, secret rotation), so Icecast knows a new password before the
  engine uses it. Icecast applies it 1–3 s after the file is written; Liquidsoap retries a
  refused connection on its own.
- **Without it** (the api alone, the tests): derived, `icecastSourcePassword(ICECAST_SOURCE_SECRET, stationId)`
  (an HMAC; `apps/api/src/modules/engine/icecast/passwords.ts`).
- The generated file therefore holds the per-station passwords; the global ones (source, relay,
  admin) stay placeholders. It is written mode 0600; the api (`node`) and Icecast both run as
  uid 1000, so Icecast can read it. Mount the volume in those two containers only.

## Fallback and intro files

- **Fallback** (`fallback`, on by default): `fallback-mount` = `/_ondes/<slug>/<format>.fallback.<ext>`,
  a file in Icecast's webroot holding the station's emergency loop in the mount's format. When
  the engine is not connected (stopped, restarting, crashed), listeners are moved to the file,
  which loops; `fallback-override all` moves them back when the engine reconnects, and
  `fallback-when-full` sends listeners above `max-listeners` there too. Measured: a listener
  connected when the engine stops keeps receiving audio, longest gap 0.4–0.7 s, and is back on
  the live stream once the engine reconnects. Icecast doesn't pace file fallbacks: a client that
  reads as fast as it can gets the file faster than real time; players read at playback speed.
- **Intro** (`intro`, off by default): `intro` = `/_ondes/<slug>/<format>.intro.<ext>`, sent to each
  new listener before the stream (a station ID). Verified byte for byte by the test.
- **Only configured once the file exists.** The api checks the assets volume
  (`ICECAST_ASSETS_DIR`, its mount of the same volume) on every sync (30 s): a missing file
  means no `<fallback-mount>`/`<intro>` for that mount, never a broken one. Without
  `ICECAST_ASSETS_DIR`, none are configured (logged once).
- **Encoding them**: `encode-assets.sh` runs `encode-assets.liq` in the pinned Liquidsoap image
  (no extra image, no ffmpeg on the host). Example for a station with the default mounts:

  ```sh
  docker run --rm --user root \
    -e JOBS="vandale/mp3:mp3:fallback vandale/aac:aac:fallback" \
    -e FALLBACK_INPUT=/in/emergency.flac \
    -v /srv/ondes/vandale/emergency.flac:/in/emergency.flac:ro \
    -v stream-assets:/assets -v ./deploy/icecast:/ondes:ro \
    --entrypoint sh savonet/liquidsoap:v2.4.6 /ondes/encode-assets.sh
  ```

  Files: `<slug>/<format>.{fallback,intro}.<ext>`, `ext` = `mp3`, `aac`, `ogg` (Opus/Vorbis:
  Icecast types webroot files by extension). Running it again when the emergency file or the
  outputs change is a worker job's work (follow-up); until then the installer (#84) or an admin
  runs it.

## Config generation and reload

- The api renders `icecast.xml` for all stations (`renderIcecastConfig`) and writes it to
  `ICECAST_CONFIG_PATH` atomically (unique temp file + rename), only when it changed: on boot,
  every 30 s (`ICECAST_SYNC_INTERVAL_MS`), and on `sync.syncNow()` after a settings change.
  Several api processes take turns through a Postgres advisory lock.
- **A station with invalid outputs keeps its last good mounts** (logged, `stream.config_invalid`
  alert). After an api restart there is no last good copy: the station's streams are left out
  until its settings are fixed.
- `entrypoint.sh` (this folder) is the container's entrypoint. It waits for the file, fills in
  the global passwords in one pass (any character allowed, XML-escaped), starts Icecast on the
  result (`/etc/icecast.xml`, mode 600), and checks the source file every 2 s
  (`ICECAST_CONFIG_POLL_SECONDS`). On a change it renders again and sends Icecast a **SIGHUP**.

**Why SIGHUP and not a restart.** Measured with the pinned image (`icecast.int.test.ts`):

| | Listeners | Sources (engines) | Applies |
|---|---|---|---|
| SIGHUP reload | stay connected; longest gap 128–143 ms (a 128k stream normally arrives in 150–250 ms bursts, so nothing audible) | stay connected | new and removed mounts, changed limits, passwords, fallback, intro: 2.8–3.6 s after the api wrote the file (1 s poll in the test + Icecast's reload queue) |
| Restart | **all cut** (within 0.3 s), players must reconnect | cut, Liquidsoap reconnects after its retry delay | everything |

A file Icecast can't parse is ignored on SIGHUP: it logs `Error parsing config, not replacing
existing config` and keeps running on the previous one (tested). Changes that need a restart:
listen sockets (port, bind address). The generator keeps them fixed.

**Icecast 2.5.0 reload deadlock.** After any `/admin/listclients` request (XML or JSON, also
`listclients.xsl`, the admin UI's "List clients" page) on a mount that had a listener, the next
SIGHUP deadlocks Icecast: it stops answering anything, and the container stays "up". Reproduced
every time; `/admin/stats` doesn't trigger it. So:
- nothing in Ondes calls `listclients*`: the poller only reads `/admin/stats`;
- `/admin/*` is never proxied by Caddy (below), so nobody outside reaches it; don't use the admin
  web UI on the internal network either;
- `entrypoint.sh` probes Icecast every 10 s (`ICECAST_WATCHDOG_SECONDS`) and kills it after three
  failed probes, so the container exits and `restart: unless-stopped` brings it back (about 20 s
  in the test, listeners cut). Re-test when the image is bumped.

## Production compose (for #84)

```yaml
services:
  icecast:
    image: libretime/icecast:2.5.0-alpine
    entrypoint: [sh, /ondes/entrypoint.sh]
    restart: unless-stopped
    environment:
      # No ICECAST_SOURCE_PASSWORD: the global one is random; stations have their own.
      ICECAST_ADMIN_USER: admin
      ICECAST_ADMIN_PASSWORD: ${ICECAST_ADMIN_PASSWORD}
    expose: ['8000']            # no `ports:`: only Caddy, the engines and the api reach it
    volumes:
      - ./icecast/entrypoint.sh:/ondes/entrypoint.sh:ro
      - icecast-config:/config:ro
      - stream-assets:/usr/share/icecast/web/_ondes:ro
  api:
    environment:
      ICECAST_CONFIG_PATH: /srv/ondes/icecast/icecast.xml
      ICECAST_ASSETS_DIR: /srv/ondes/stream-assets
      ICECAST_PUBLIC_HOSTNAME: stream.example.org
      ICECAST_URL: http://icecast:8000
      ICECAST_ADMIN_USER: admin
      ICECAST_ADMIN_PASSWORD: ${ICECAST_ADMIN_PASSWORD}
    volumes:
      - icecast-config:/srv/ondes/icecast
      - stream-assets:/srv/ondes/stream-assets:ro
```

`ICECAST_ADMIN_USER` is the one name for the admin user, in the api and in `entrypoint.sh`
(the dev compose maps it to the image's own `ICECAST_ADMIN_USERNAME`, for its own entrypoint).

## Caddy on 443

Streams are served on their own host name (the `ICECAST_PUBLIC_HOSTNAME`), so stream URLs are
`https://stream.example.org/<slug>/mp3`. Caddy gets the certificate (Let's Encrypt) and proxies
only the public paths:

```caddyfile
stream.example.org {
	# Mounts are /<station-slug>/<format>; slugs are [a-z0-9-]. Plus the status JSON for
	# players/embeds. Never /admin (Icecast's admin API stays on the internal network): it
	# has the same shape as a mount, hence the explicit exclusion.
	@public {
		path_regexp ^/([a-z0-9-]+/[A-Za-z0-9_.-]+|status-json\.xsl)$
		not path /admin /admin/*
	}
	handle @public {
		reverse_proxy icecast:8000 {
			# Live audio: no buffering, no response timeout.
			flush_interval -1
			transport http {
				read_timeout 0
				write_timeout 0
			}
		}
	}
	handle {
		respond 404
	}
}
```

- `flush_interval -1` matters: otherwise Caddy buffers the never-ending response and players
  stall. Caddy streams HTTP/1.1 and HTTP/2 responses.
- Checked against the integration stack with `caddy:2.10.2-alpine` and `tls internal`: MP3 and
  AAC play over HTTP/2 + TLS (ffprobe/ffmpeg decode them), `/admin/stats` and
  `/admin/listclients` answer 404. Real players (browsers, VLC, mobile) still need a check on
  the installed server.
- Engines connect to `icecast:8000` on the internal network, never through Caddy.
- Behind a CDN (Cloudflare), add a cache-bypass rule for the stream host.
- **GDPR.** Icecast logs requests to stdout; behind Caddy every request comes from Caddy's
  address, so Icecast's logs hold no listener IP. Caddy's access log is off unless configured
  (keep it off for the stream host, or drop `remote_ip`). The stats poller stores counts only.

## Listener stats and alerts

- `apps/api/src/modules/engine/icecast/poller.ts` reads `/admin/stats` every 15 s and records,
  per mount and minute, the number of samples, sum, min and max of listeners, and how many
  samples had the engine connected (`stream_listener_stat`, `@ondes/db` `recordListenerSamples`
  / `listListenerStats`). Listeners parked on a mount's fallback file count for that mount.
- Retention (`downsampleListenerStats`, hourly): minute buckets older than 30 days are folded
  into hour buckets; hour buckets older than two years are deleted. About 1,440 rows per mount
  per day for the last 30 days, then 24.
- Alerts, through #33's framework: `stream.source_missing` (warning) after 60 s without the
  engine on a mount, resolved once it has been back for 30 s; `stream.config_invalid` (warning);
  `stream.icecast_unreachable` (critical, every station) after 4 failed polls, resolved on the
  next good one.
